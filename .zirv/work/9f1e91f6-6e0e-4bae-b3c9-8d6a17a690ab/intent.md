# Intent

## Problem

`Glubiz/zirv-flow` is an empty public repository (LICENSE, a one-line README, an
uncommitted `zirv init` stub in `.zirv/`). It should be run exactly like
`Glubiz/zirv-cli`: same governance, agent context, CI/CD gates, conventions and
GitHub configuration. It also has no architecture or plan yet.

Zirv Flow is a self-hosted marketing automation tool written in Rust. It lets
marketers connect internal and external data sources, segment the people in
the business from that data, and run automation flows for everyone or for a
segment. Segmentation, data sources and integrations are the focus.

## Desired outcome

1. Repository files mirroring zirv-cli, adapted to Zirv Flow:
   - `.github/`: FUNDING, issue forms (bug, feature, config), PR template,
     `ci.yaml` (merge gate on PRs to `main`/`release/**`) and `cd.yaml`
     (build + GitHub release on merge to `main`).
   - `.gitignore`, `.gitattributes`, `.config/nextest.toml`,
     `.claude/settings.json`.
   - `.zirv/`: `.settings.toml`, `.shortcuts.yaml`, `commands/` (test, commit),
     `context/{common,claude,codex}.md`, `ctx.toml`; `CLAUDE.md` and
     `AGENTS.md` generated by `zirv context sync --generate`.
   - `README.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`,
     `DISCLAIMER.md`, `CHANGELOG.md`.
   - `scripts/`: test-presence gate, advisory security scan, changelog
     generator, each with `--self-test`.
   - A minimal Rust 2024 crate `zirv-flow` (one binary) so every gate has
     something real to run.
2. GitHub settings mirroring zirv-cli: description, topics, discussions on,
   "Protected Main" and "Protected Tags" rulesets (same rules and admin
   bypass), the same non-product-specific labels (`security`,
   `severity:{blocker,major,minor}`), Actions default token read-only.
3. An architecture document and a development plan with milestones, committed
   under `docs/`, with the milestones also created as GitHub milestones.
4. All of it delivered on a branch through a PR, with CI green.

## Constraints

- Never commit or push to `main`; branch and open a PR. No `Co-Authored-By` or
  "Generated with Claude Code" lines.
- No competing product is named anywhere: files, commits, PR, issues,
  milestones, repo settings.
- zirv-cli-only machinery is not copied: the README-features gate, `zirv
  verify --builtin`, native-install platform jobs, benchmarks, the
  Homebrew/Chocolatey jobs and their environments, the `axis:*` and
  `native-harness` labels, the brand guide, and the zirv-cli memory bank.
- Repo-layer `.zirv/` config is untrusted and may only narrow, as in zirv-cli.
- Secrets are not read or copied (`gh secret` is blocked, and none are needed
  yet).

## Open questions

- Core architecture choices (data-source model, frontend stack, extension
  model, storage/queue) are routed to the supervisor before the architecture
  document is written.

## Acceptance criteria

- [ ] Every repository file listed in outcome 1 exists, adapted to Zirv Flow
      with no stale zirv-cli references (paths, issue numbers, product text).
- [ ] `zirv context sync --check` passes; `CLAUDE.md`/`AGENTS.md` are generated,
      not hand-written.
- [ ] `cargo build`, `cargo nextest run --no-fail-fast`, `cargo fmt -- --check`,
      `cargo clippy --all-targets -- -D warnings` pass locally, and every script
      `--self-test` passes.
- [ ] The two rulesets, labels, description, topics and discussions on
      `Glubiz/zirv-flow` match the zirv-cli values named in outcome 2
      (verified with `gh api`).
- [ ] `docs/architecture.md` and `docs/roadmap.md` exist; each milestone has a
      goal, scope, exit criteria and dependencies, and matches a GitHub milestone.
- [ ] `grep -ri` for competing product names over the tree, commits and PR body
      returns nothing.
- [ ] PR open against `main` with CI passing.
