# Decisions (#213)
- minijinja 2.24.0 (2026-08-12; 3.0.0 is 14 days old, 3.0.x too new): stable 2.x API, older than two weeks.
- Features builtins, macros, serde, fuel, multi_template: fuel does not compile without multi_template in 2.24; no loader is set, so include/extends find nothing. No json/urlencode/debug/unicode.
- Advisory check: no RustSec advisory lookup possible offline; CI rustsec/audit-check covers it. minijinja adds only memo-map.
- Output limit: CappedWriter via render_captured_to; webhook body also has a running byte budget across all strings.
- Limits: fuel 200000, recursion 64, source 256 KiB, html 512 KiB, text 256 KiB, subject 998 (RFC 5322), header value 4096, webhook body 256 KiB.
- Context: person/event as BTreeMap<String, serde_json::Value>, message.id, system.unsubscribe_url/preferences_url; ordered so bytes are deterministic.
- Webhook body stored as JSON text and parsed before rendering; only string values render; keys with template syntax are refused (template_in_key); a string that is exactly one {{ expr }} is evaluated as an expression and keeps its JSON type.
- Marketing render requires https unsubscribe URL and an <a> to it in the HTML (else typed error); unsubscribe and preference URLs are not click-rewritten.
- Subject and header values: control characters become spaces (header injection).
- Inert tracking: every web link becomes {base}/inert, token function never called.
- Blocking codes: unsupported_schema, unsupported_channel, unsupported_mode, missing_content, content_too_large, syntax_error, unknown_merge_field, missing_unsubscribe, missing_sender, invalid_json_body, template_in_key. Warnings: missing_lang, insecure_link, html_near_clip (90000 bytes).
- Workspace members use crates/*, so no members edit was needed; hashbrown not needed (no sets of hashed keys).
